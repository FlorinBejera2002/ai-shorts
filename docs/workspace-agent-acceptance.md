# Workspace Agent: acceptance and operation audit

Audit date: 2026-09-23. Source: the original Notion ticket, saved verbatim in `.cache/workspace-agent/spec.md` (AC01–AC35, T01–T21). This is a working-tree implementation audit, not a production certification. Other agents are still extending the catalog; changes after this snapshot need the corresponding rows updated.

**The complete ticket is not yet verified.** The implemented agent executes real platform services for the catalogued operations. Coverage is still incomplete for several existing manual operations, and the full ten-recording, branded, reviewed, published workflow has not been demonstrated by the frontend tests below. A mocked browser API response is not evidence of a successful production render, provider publication, or LLM planning decision.

## Evidence and terminology

- **Code**: implementation inspected; does not imply execution passed.
- **UI fixture verified**: `frontend/tests/workspace-agent.browser.mjs`, run against the local frontend with every application API intercepted. Covers persistent shell/header identity and draft, valid/invalid video registration, document attachment IDs, explicit suggestion acceptance and revision, idempotent retry, revision approval, opt-in navigation, asynchronously completed story targeting, mobile dialog/Escape/focus, actual local MP4 fixture metadata via a mocked authorized clip endpoint, dark mode and reduced motion. No real account or database was mutated.
- **Unit verified**: `frontend/tests/workspace-agent.test.mjs`: route safety, route/resource activity matching, result escaping/field filtering, revision reconciliation, polling policy, clip context, request identity and control revision. An additional provider-consent versus unschedule regression covers the final approval UI; record its final run alongside the root task checks.
- **Static verified**: frontend TypeScript and scoped Oxlint passed. The changed-scope React Doctor run reported 78 with two pre-existing Studio hook warnings. That scan is not complete accessibility or production performance validation, and untracked-file inclusion should not be assumed.
- **Backend test source**: named Go/Studio tests below exist and were inspected. Their existence alone is not recorded as a pass here. The root task owns executing and reporting isolated database/service integration suites.
- **Library integration verified**: `go test -race ./internal/projects ./internal/workspaceagent` passed against the dedicated disposable integration database after the folder/move implementation. `projects/agent_library_test.go` verifies receipts, ownership, concurrent expected-state edits, stale Undo, folder-cycle rejection, delete promotion and preservation of a clip's source job. Later edits to either package require their own relevant checks.
- **Limited**: some of the criterion or operation works; remaining behavior or validation is named.
- **Gap**: no equivalent action or required verification was found. Secure manual handling of passwords/OAuth/payments is an intentional boundary, not an invitation to collect secrets in chat.

Primary code: `frontend/src/components/workspace-agent/`, `frontend/src/components/dashboard/dashboard-shell.tsx`, `backend/internal/workspaceagent/`, `editor/packages/sneepcut-server/src/agent.ts`. Actual route inventory: `frontend/src/App.tsx`. Legacy `/dashboard/project`, `/dashboard/history`, review and analytics routes redirect; they must not be advertised as independent new workspaces.

## Highest-priority remaining work

1. Prove T01/T02/T09 with the real synthetic-media pipeline, accepted version and protected end segment. This is the central product outcome; navigation and mock render responses cannot substitute for it.
2. Complete existing manual operations that directly affect the requested video: clip style/transition service, project-local brand, Studio media ingestion and actual selection/playhead context. Keep version guards and service parity.
3. Prove external exact approval, destination-level partial outcomes, stale media/account changes and cancellation through a real database plus provider fakes. No live publication is necessary to test these boundaries.
4. Verify expanded preferences and script archive/history/restore against their manual flows; finish script export and publishing media attachment. Project organization now has disposable-DB race coverage. Keep MFA/OAuth/password/payment/permanent deletion in explicit secure human flows.
5. Complete actual device speech/gallery and screen-reader checks, plus malicious-document/transcript and two-tab recovery suites. Record each result separately from unit/mock coverage.

The implementation should not be described as full platform control or the ticket marked fully verified until these operation and scenario gaps are resolved or explicitly accepted by the product owner.
