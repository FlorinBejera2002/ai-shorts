# Shadcn redesign

Scope: 22 localized pages redesigned with shadcn; Home retains its original cinematic design per the latest user instruction. All 23 pages have separate Notion tickets, plus two tickets for shared controls and navigation. Ticket IDs and links are in `redesign-tickets.json`; live status is maintained in Notion, not in that manifest.

## Implementation

- Shared shadcn-style Cards, Buttons, Inputs, Textareas, Labels, NativeSelects, Tabs, Switches, Sliders, Dialogs, Accordions, progress indicators and single-choice groups. Interactive primitives use the existing Radix dependency.
- Public pages other than Home: theme-aware navigation, mobile Sheet, footer, pricing cards/FAQ and legal table of contents.
- Home: original dark cinematic hero, workflow/features sections, footer and floating navigation. Its native mobile menu and language controls are isolated from shared shadcn components.
- Auth pages: shared split layout and theme-aware forms, retaining existing registration, sign-in and password recovery handlers.
- Studio pages: consistent page headers and sections, Recharts-based analytics with accessible data tables, clip library/workspace/editor, create controls, calendar, history, publishing, brand, billing and account settings.
- Logo backgrounds remain transparent in the sidebar. English/Romanian routing and theme preferences are retained.

The redesign changes presentation and interaction structure. It does not provision external billing, OAuth, publishing or AI services.

## Verification commands

Run from `frontend`:

```powershell
npm.cmd test
npm.cmd run typecheck
```

Build and refresh the Docker frontend from the repository root:

```powershell
docker compose build frontend
docker compose up -d --no-deps --force-recreate frontend nginx
```

The opt-in browser harness requires an installed Playwright module and its Chromium/Firefox browsers. Set `SNEEPCUT_PLAYWRIGHT_MODULE` to the absolute `playwright/index.mjs` path and `PLAYWRIGHT_BROWSERS_PATH` to its installed browser directory, then run from `frontend`:

```powershell
$env:SNEEPCUT_BROWSER_MUTATIONS='allow-synthetic-account'
$env:SNEEPCUT_ALL_PAGES='1'
node scripts/test-dashboard-design.mjs
```

`SNEEPCUT_INTERACTIONS_ONLY=1` runs the focused interaction checks instead of the full route/sidebar matrix. Leave it unset for full verification.

If Firefox cannot start on the host, `SNEEPCUT_MOBILE_ENGINE=chromium` explicitly selects a Chromium mobile fallback. Result names identify the actual browser; a fallback run is not evidence of a Firefox pass.

## Browser coverage and safety

The full harness checks 23 routes in Chromium desktop light, Chromium desktop dark and Firefox Romanian mobile: 69 route cases. It also checks empty-state routes, dashboard filtering, accessible chart data, sidebar navigation/preferences/focus, source tabs, switches/sliders, editor dialogs, script selection/validation, account forms, pricing FAQ and the public mobile Sheet.

Only uniquely identified synthetic users, terminal jobs, clips, calendar drafts and brand/profile settings are created in the local Docker database. Cleanup targets those exact synthetic users and their records in `finally`. Video bytes are generated by FFmpeg and intercepted in the browser; no render job is enqueued. Calendar drafts are planning records, not external publications.

Screenshots and route results are written to ignored `test-results/all-pages`, `test-results/dashboard-design` and `test-results/sidebar` directories. This verification does not establish that paid AI, payments, external OAuth or social publishing are configured or working end to end.

## Local address caveat

Browser automation explicitly resolves `localhost` to IPv4 for the Docker nginx listener. A separate native Next.js process may also listen on IPv6 port 3000. Do not stop unrelated processes or assume that both addresses serve the same application instance.
